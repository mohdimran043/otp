Moving large files across an air gap
with a monitor and a camera

A technical overview of the Optical Transport Platform: what it does, how fast it goes, and what governs both.

Measured on commodity hardware — a 20-core workstation and an integrated 1080p webcam. Every figure in this document comes from a test in the repository, not an estimate.

1 · What the system is

Two computers with no network between them. One displays a file as a sequence of encoded images; the other photographs them and reassembles the file, then verifies it against a cryptographic hash the sending side declared before anything was drawn.

The only channel between them that is not optical carries acknowledgements — small signed records saying "chunk 47 arrived intact". That return path is what turns a hopeful broadcast into a lossless transfer, and it is the single most important idea in the design.

Figure 1. Data crosses as light and cannot be acknowledged optically — a lost frame produces no report, only silence. So the return path carries the acknowledgements, and the sender never advances past a chunk it has not heard about.

The guarantee, in one sentence. A chunk is displayed repeatedly until a signed acknowledgement for it arrives. Nothing else in the system promises delivery; error correction is an optimisation on top of that, not the guarantee.

2 · Speed: what the sender can offer

Throughput is bytes per frame × frames per second. Bytes per frame is set by how many cells the grid has and how many bits each cell carries; frames per second by the panel. Both are operator-controlled from the Settings page.

Capacity depends on the grid, not the cell size. A 256×256 grid carries the same 30 226 bytes whether its cells are 4 or 8 pixels. Cell size buys one thing only: the camera's ability to resolve a cell. It costs screen area and nothing else.

Refresh rate is a ceiling, not a target

A 144 Hz panel can show 144 frames a second. Setting the sender to 144 fps does not transfer 144 frames' worth of data, because the receiver cannot read that fast — and a frame nobody reads costs a render and delivers nothing. The panel's rate is measured in the browser on the Settings page (requestAnimationFrame intervals; 144 Hz shows as 6.94 ms) and offered as an upper bound.
